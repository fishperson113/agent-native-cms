# Milestone 10 — Durable audit event stream

## Status

Implemented.

## Goal

Create a durable, append-only audit event log that records MCP, authentication, key-management, tenant-management, and content lifecycle activity. Make it replayable and streamable so a visual log viewer can be added later without changing producers.

## Important boundary

The audit event stream is not the MCP protocol event store and is not application state reconstruction. It is an immutable operational history:

```text
MCP/auth/application event
  ↓ append
PostgreSQL audit_events
  ├─ paginated history query
  ├─ cursor replay by event ID
  └─ PostgreSQL LISTEN/NOTIFY wake-up
          ↓
Admin SSE stream → future visual log UI
```

PostgreSQL is sufficient for the current scale. Kafka, Redis Streams, and a separate observability platform remain unnecessary until measured load requires them.

## Event envelope

Each event has a stable shared envelope:

- `id`: monotonic `bigint` cursor generated by PostgreSQL.
- `event_id`: UUID for global identity.
- `occurred_at`: server timestamp.
- `event_type`: versioned dotted name such as `mcp.tool.completed.v1`.
- `actor_role`: `admin | tenant | system | anonymous`.
- `credential_id`: nullable UUID; never the key value or hash.
- `tenant_id`: nullable UUID.
- `session_id`, `correlation_id`: nullable identifiers.
- `resource_type`, `resource_id`: nullable resource reference.
- `outcome`: `success | denied | failed`.
- `duration_ms`: nullable integer.
- `metadata`: small JSON object containing allowlisted, non-secret fields.

The schema is append-only at the application layer: no update or delete use cases are provided.

## Initial event catalog

### Authentication and sessions

- `mcp.authentication.succeeded.v1`
- `mcp.authentication.failed.v1`
- `mcp.session.opened.v1`
- `mcp.session.closed.v1`
- `mcp.session.expired.v1`

### Tool execution

- `mcp.tool.started.v1`
- `mcp.tool.completed.v1`
- `mcp.tool.denied.v1`
- `mcp.tool.failed.v1`

### Administration

- `admin.tenant.created.v1`
- `admin.tenant.status_changed.v1`
- `admin.credential.issued.v1`
- `admin.credential.revoked.v1`
- `admin.session.closed.v1`
- `admin.article.viewed.v1`
- `admin.article.deleted.v1`

Content and presentation identifiers, result state, artifact hash, and compile duration can be included in allowlisted metadata, preserving the useful fields from the existing MCP observer.

## Write guarantees

- Security-sensitive and administrative events are written durably before reporting success.
- Mutation audit events are appended in the same database transaction as the business change when possible.
- Failed/denied attempts that have no business transaction are appended independently.
- Event writing failures for admin/key mutations fail the operation closed.
- High-volume informational events may later use buffering, but the first version favors correctness.
- Never record bearer keys, key hashes, full Markdown, TSX source, compiled code, authorization headers, or arbitrary request payloads.

## Query and streaming interfaces

### History

- Admin-only cursor pagination ordered by `id`.
- Filters: time range, event type, outcome, tenant, credential, session, correlation, and resource.
- Tenant access to audit history is deferred; first version is admin-only.

### Live stream

- Admin-only Server-Sent Events endpoint.
- Use the audit `id` as the SSE event ID.
- Accept `Last-Event-ID` and replay missed rows before switching to live delivery.
- Use PostgreSQL `LISTEN/NOTIFY` only as a low-latency wake-up signal; always fetch canonical rows from `audit_events`.
- Send heartbeats and close cleanly on client disconnect.
- A reconnect must not silently skip events; duplicate delivery is acceptable and consumers deduplicate by `id`.

## Retention and indexes

- Keep events indefinitely for the PoC.
- Index `occurred_at`, `tenant_id + id`, `event_type + id`, `credential_id + id`, and `correlation_id`.
- Document a future archival/retention job, but do not implement deletion yet.

## Acceptance tests

- A successful tenant tool call produces correlated started/completed events.
- Denied, invalid-key, revoked-key, and failed tool calls produce safe events.
- Tenant/key administrative changes and their audit event commit atomically where applicable.
- Admin article deletion and `admin.article.deleted.v1` commit atomically and record the tenant/article IDs without article content.
- Secrets and uploaded source never appear in stored metadata or stderr logs.
- History pagination is stable while new events are appended.
- SSE replays from `Last-Event-ID`, continues live, and tolerates reconnects.
- Admin authentication is required for query and streaming endpoints.
- Two simultaneous viewers receive the same ordered event IDs.

## Exit criteria

- All authentication, session, authorization, admin, and tool lifecycle paths emit versioned events.
- Operators can query history and watch a resumable live stream without Kafka or Redis.
- Existing ad-hoc JSON stderr telemetry is adapted to the same event vocabulary or retained only as a sink, not as the source of truth.
- The event contract is ready for a later visual dashboard.

## Non-goals

- Building the visual log dashboard.
- Full event sourcing of CMS state.
- Distributed tracing infrastructure.
- External SIEM/export pipelines.
- Tenant-visible audit screens.
